## 1. Анализ

Проект «РАЗЛОМ // СЕКТОР-9» — top-down space shooter на кастомном ECS-движке
(trixt0r/ecs). Ввод обрабатывается двумя изолированными системами:

- **InputManager** (`src/game/input.ts`) — клавиатура (WASD/стрелки) + тач-джойстик + геймпад → нормализованный `MoveAxis { x, y }`
- **InputSystem** (`src/game/systems/InputSystem.ts`) — мышь (прицеливание) + тач (стрельба) → события `onAimUpdate`, `onFiringChanged`

Архитектура разделяет **абстракцию ввода** и **потребление ввода** системами.
UI получает события геймпада через хуки жизненного цикла, а активный экран
регистрирует свои навигационные обработчики в общем `gamepadNavRef`.

### Этап 1 — Базовая поддержка ✅

- Левый стик / крестовина (D-pad) — перемещение игрока в игре
- Кнопка A (Cross) — подтвердить / войти
- Кнопка B (Circle) — назад / отмена
- Кнопка Start — пауза
- Определение подключения/отключения геймпада

### Этап 2 — Базовая навигация по UI ✅

- Главное меню, пауза и game over: перемещение фокуса по кнопкам
- Настройки и прокачка: навигация по пунктам
- Визуальный индикатор фокуса (жёлтая рамка/свечение)
- Переключение вкладок прокачки кнопками L/R (LB/RB)

### Этап 3 — Доработка навигации по замечаниям ✅

Исправлено после проверки этапа 2:

1. **Без подписей кнопок.** Удалены символы `✕`/`○` с кнопок паузы и game over
   (и любые другие подписи кнопок геймпада). Фокус показывается только
   визуальной подсветкой.
2. **Помощь.** D-pad/левый стик прокручивают текст справки (быстрое
   перемещение влево/вправо — на пол-экрана), A и B возвращают назад.
3. **Настройки.** Фокус проходит по всем 11 пунктам: три слайдера, выбор
   трека, кнопка прослушивания, тест звука, движок физики, два языка,
   сброс прогресса и «Назад». Слайдеры регулируются влево/вправо, списки
   открываются по A, навигация внутри списка — вверх/вниз, выбор — A,
   закрытие — B. Открытый список перехватывает B вместо выхода с экрана.
4. **Прокачка.** Навигация идёт не только по вкладкам, но и по всем объектам
   внутри вкладки: строкам корабля/щита, карточкам оружия и его линиям,
   карточкам дронов и их линиям, строкам бонусов. A покупает выбранное,
   L/R (LB/RB) и D-pad влево/вправо переключают вкладки, вверх/вниз —
   перемещают фокус. Фокус сбрасывается на первый пункт при смене вкладки и
   автоматически прокручивается в видимую область.
5. **Game over.** Кнопки расположены вертикально, навигация вверх/вниз
   совпадает с визуальным порядком.

### Этап 4 — 8BitDo Lite 2 и переработка меню ✅

Исправлено после проверки на 8BitDo Lite 2 (D-input):

1. **Нестандартная раскладка.** Устройство сообщает собственные индексы
   кнопок: A=0, B=1, X=3, Y=4, L=6, R=7, Select=10, Start=11. Добавлены две
   раскладки (`STANDARD_BUTTONS`, `DINPUT_BUTTONS`) и выбор по
   `gamepad.mapping`, id (`8bitdo`/`2dc8`) и числу кнопок (15–16).
2. **D-pad.** В D-input 8BitDo отдаёт крестовину как HID hat switch на оси 9,
   а не кнопками 12–15. Добавлен `decodeHat()`, нейтральное значение вне
   диапазона `[-1.05, 1.05]` игнорируется. Легаси-оси 5/6 применяются только
   к устройствам с `axes.length <= 6`.
3. **Пауза.** Start теперь читается по выбранной раскладке: 9 для стандартных
   геймпадов и 11 для 8BitDo D-input. ZL/B8 больше не открывает паузу.
4. **Настройки.** Экран перестроен вертикально и разделён на группы «Звук»,
   «Интерфейс», «Прогресс». Трек и «Прослушать» идут друг под другом, язык
   выбирается выпадающим списком (как трек), физический движок перенесён в
   «Отладку». Фокус — 9 пунктов.
5. **Помощь.** Добавлена подсказка про переключение вкладок прокачки L/R.

## 2. Архитектурные решения

### 2.1. GamepadManager — отдельный модуль ввода

`src/game/gamepad.ts` — аналог InputManager, но для геймпада.

- Использует Web Gamepad API (`navigator.getGamepads()`)
- Опрос состояния в каждом кадре игрового цикла
- Поддержка стандартных раскладок (Xbox, PlayStation, HID)
- Мёржит данные стика и D-pad
- Мёртвая зона стика — 0.15, кнопок/D-pad — 0.5
- Одноразовые нажатия через `consumePress()`

**Маппинг кнопок (стандартный Gamepad API):**

| Функция | PlayStation | Xbox | Виртуальный код |
|---------|-------------|------|-----------------|
| Подтвердить | Cross | A | `GamepadA` |
| Отмена | Circle | B | `GamepadB` |
| X / Y | Square / Triangle | X / Y | `GamepadX` / `GamepadY` |
| Вкладка влево | L1 | LB | `GamepadLB` |
| Вкладка вправо | R1 | RB | `GamepadRB` |
| Пауза | Options | Start | `GamepadStart` |
| Select | Share | View | `GamepadSelect` |
| D-pad | 12–15 | 12–15 | `GamepadDpadUp/Down/Left/Right` |
| Левый стик | оси 0, 1 | оси 0, 1 | — |

**Раскладка D-input (8BitDo Lite 2 и совместимые):**

| Функция | Индекс / ось |
|---------|--------------|
| A / B | 0 / 1 |
| X / Y | 3 / 4 |
| L / R (LB/RB) | 6 / 7 |
| Select / Start | 10 / 11 |
| D-pad | hat switch, ось 9 |

Устройства делятся на два профиля через `resolveGamepadProfile()`:

- **standard** — `mapping === "standard"` или неизвестное устройство:
  стандартные индексы кнопок (A=0, B=1, X=2, Y=3, L/R=4/5, Select/Start=8/9),
  D-pad кнопками 12–15.
- **8bitdo_dinput** — 8BitDo Lite 2 и совместимые (id с `8bitdo`/`2dc8`
  либо 15–16 кнопок и hat-ось): X/Y=3/4, L/R=6/7, Select/Start=10/11,
  D-pad — hat switch на оси 9.

Стандартный профиль никогда не читает hat-ось, поэтому обычные геймпады
(Xbox, PlayStation, Switch Pro и т.п.) продолжают работать по стандартной
раскладке.

**Логика мёрджа стик/D-pad:** приоритет у стика, если он выходит за мёртвую
зону; иначе используется D-pad; иначе `{ x: 0, y: 0 }`.

### 2.2. Интеграция с InputManager

- `InputManager.setGamepadSource()` подключает источник геймпада
- Геттер `axis` объединяет клавиатуру, тач и геймпад (геймпад приоритетнее)
- `consumePress()` поддерживает виртуальные коды геймпада
- `clear()` сбрасывает состояние при паузе

### 2.3. Контракт навигации UI

Активный экран регистрирует обработчики в `gamepadNavRef`
(`src/ui/ScreenRouter.tsx`):

```typescript
interface GamepadNavHandlers {
  up: () => void;
  down: () => void;
  left: () => void;
  right: () => void;
  tabLeft?: () => void;   // LB/L1
  tabRight?: () => void;  // RB/R1
  confirm: (() => void) | null;  // A
  cancel?: (() => void) | null;  // B
}
```

- `App.tsx` вызывает `confirm`/`cancel` активного экрана; если экран их не
  зарегистрировал — работает fallback по текущему экрану.
- `cancel` позволяет экрану перехватить B (например, закрыть выпадающий
  список в настройках) и не выходить сразу.
- `ScreenRouter` передаёт во все экраны `isGamepad` и `gamepadNavRef`.

### 2.4. Управление фокусом

`src/hooks/useGamepadFocus.ts`:

- Хранит `focusIndex` и список из `count` элементов
- `onNavUp/Down` — перемещение по списку с зацикливанием
- `onNavLeft/Right` — перемещение при `depth > 1` (вкладки)
- Клампит индекс при изменении `count` (после покупки/раскрытия строк)
- Безопасен при `count <= 0`

Экраны самостоятельно решают, что делать по A/B/L/R, и передают в вкладки
`focusedId` — идентификатор выбранного действия. Вкладки только подсвечивают
строку с этим id и не регистрируют собственную навигацию.

### 2.5. Визуальный индикатор

- Общий стиль для строк прокачки — `gamepadFocusStyle(focused)` в
  `src/ui/upgrade/model.ts`: жёлтая рамка `#ffb84d`, подложка и свечение.
- Кнопки (`GameButton`, `TabButton`) используют переменную `--btn-c` и
  `drop-shadow`, потому что `clip-path` обрезает обычный `box-shadow`.
- У элементов с фокусом выставляется `data-gamepad-focused="true"` — по нему
  выполняется `scrollIntoView({ block: "nearest" })`.

## 3. Реализация

### 3.1. GamepadManager

`src/game/gamepad.ts`:

- Опрос через `navigator.getGamepads()` каждый кадр
- Нормализация оси движения: левый стик + D-pad
- Все основные кнопки: A, B, X, Y, LB, RB, LT, RT, Start, Select, L3, R3, D-pad
- Одноразовые нажатия через `consumePress()`
- Автоматическое обнаружение подключения/отключения

### 3.2. GameContext и жизненный цикл

`src/game/core/GameContext.ts`:

- Создание `GamepadManager`, подключение к `InputManager`
- `poll()` и обработка кнопок в `handleDebugKeys()` — каждый кадр, включая
  меню и паузу
- Start — пауза (D-pad для паузы не используется, чтобы не конфликтовать с
  навигацией)
- A/B, D-pad и LB/RB пробрасываются в хуки
- Навигация левым стиком — edge-triggered с задержкой и автоповтором

`src/game/core/GameHooks.ts`, `src/hooks/useGameLifecycle.ts`:

- `onGamepadConfirm`, `onGamepadCancel`
- `onGamepadNavUp/Down/Left/Right`
- `onGamepadTabLeft/Right` (LB/RB)

### 3.3. App и ScreenRouter

`src/App.tsx`:

- `gamepadConfirm`/`gamepadCancel` через refs (без stale closure)
- B сначала вызывает экранный `cancel`, затем fallback
- Start — пауза/продолжение
- Навигационные хуки прокидываются в `ScreenRouter`

`src/ui/ScreenRouter.tsx`:

- Передаёт `isGamepad`, `gamepadNavRef` в MainMenu, Settings, Help, Upgrade
  и оверлеи паузы/game over

### 3.4. Экраны

- **MainMenu** — навигация вверх/вниз, A — выбор, фокус на кнопках.
- **PauseOverlay** — навигация вверх/вниз, A — выбор, B — в главное меню;
  подписи кнопок удалены.
- **GameOverScreen** — кнопки вертикально, навигация вверх/вниз, A — выбор,
  B — в главное меню; подписи кнопок удалены.
- **HelpScreen** — D-pad/стик прокручивают текст, A/B — назад.
- **SettingsScreen** — 9 пунктов: три слайдера, выбор трека и прослушивание
  друг под другом, тест звука, язык (выпадающий список), сброс прогресса,
  «Назад». Группы «Звук», «Интерфейс», «Прогресс». Слайдеры регулируются
  влево/вправо, списки открываются по A, навигация внутри списка — вверх/вниз,
  выбор — A, закрытие — B. Открытый список перехватывает B.
- **DebugScreen** — вертикальный выбор физического движка
  (Planck.js / Custom / p2-es), помимо FPS, бессмертия, стартовой волны, врагов
  и бонусов.
- **UpgradeScreen** — единый список действий активной вкладки, A — покупка,
  вверх/вниз — фокус, L/R и влево/вправо — вкладки, B — назад.
- **Вкладки прокачки** (`ShipTab`, `ArmoryTab`, `DronesTab`, `BonusesTab`) —
  подсветка элемента по `focusedId`, без собственной навигации.

### 3.5. Доработка этапа 3

- `useGamepadFocus`: убраны неиспользуемые внешние обработчики, добавлен
  клампинг при изменении `count`, защита от пустого списка, очистка таймера.
- `ScreenRouter`: расширен `GamepadNavHandlers` (`tabLeft`, `tabRight`,
  `cancel`).
- `SettingsScreen`: нативные `<select>` заменены на кастомные кнопки со
  списками, чтобы работали A/B и навигация; добавлен перехват B.
- `App`: B вызывает экранный `cancel` перед fallback.
- Вкладки прокачки переведены на централизованный `focusedId`.
- Удалены подписи `✕`/`○`.

## 7. Риски и ограничения

- **Браузерная совместимость**: Web Gamepad API поддерживается в Chrome,
  Firefox, Edge, Safari 16.4+. Для старых версий — graceful degradation.
- **Мультигеймпад**: API поддерживает до 4 геймпадов, используется первый
  подключённый.
- **Haptic feedback**: не реализовано (требует GamepadHapticActuator).
- **Калибровка стиков**: настраивается только мёртвая зона; калибровка под
  конкретное устройство ограничена Web Gamepad API.
- **Нестандартные раскладки**: DInput-геймпады могут отличаться индексами
  кнопок и способом передачи D-pad. Сейчас поддержаны стандартная раскладка и
  вариант 8BitDo (hat на оси 9); для новых устройств может понадобиться
  отдельный профиль.
- **Мёртвая зона навигации**: для стика в меню используется отдельный порог
  и автоповтор, чтобы избежать случайных сдвигов.
