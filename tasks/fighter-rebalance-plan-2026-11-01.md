# План ребаланса истребителя (Fighter)

**Статус:** ✅ выполнен.
**Снимок:** 2026-11-01
**Причина:** файтер убивает игрока почти мгновенно — DPS в CUT режиме ~6.8/с,
за 15 секунд CUT — ваншот.

---

## 1. Результаты моделирования боя 1v1

### Текущее поведение (как есть)

| Фаза | Длительность | Действие файтера | Урон игроку |
|---|---|---|---|
| PATROL → SEARCH | ~1.5 с | Сближение, обнаружение | 0 |
| SEARCH → CUT | ~0.5 с | Облет, ожидание | 0 |
| **CUT** | **∞ (пока игрок кружит)** | **Непрерывная стрельба** | **~6.8/с** |
| EVADE | 0.65 с | Вираж | 0 |
| COOLDOWN | 1.2 с | Свободный полёт | 0 |
| **Всего за цикл** | **~3.9 с** | **1 burst (2 болта)** | **~2.73** |

**DPS за цикл:** 2.73 / 3.9 = **0.7 урона/с**

**НО:** если игрок не прерывает цикл (продолжает кружить), CUT повторяется
без паузы — каждый новый fireGate открывает burst сразу:

| Время | Действие | Накопленный урон |
|---|---|---|
| 0 с | Начало CUT | 0 |
| 1 с | 1 burst | ~2.73 |
| 2 с | 2 burst | ~5.46 |
| 5 с | 5 burst | ~13.65 |
| 10 с | 10 burst | ~27.3 |
| 15 с | 15 burst | ~40.95 (ваншот на волне 1+) |
| 20 с | 20 burst | ~54.6 |
| 30 с | 30 burst | ~81.9 |

### Проблемы

1. **Непрерывная стрельба в CUT.** `tryFire()` вызывается каждый кадр,
каждое новое окно открывает burst без cooldown. Фактически файтер стреляет
без перезарядки — DPS ~6.8/с вместо ~0.7/с за цикл.
2. **Commit range 620 px.** Файтер может зайти с standoff (266 px на волне 1)
и сразу перейти в ATTACK, не давая игроку времени на реакцию.
3. **Burst interval 0.09 с.** Слишком короткий — создаёт ощущение «пулемёта».
4. **Fire max time 1.25 с.** Слишком большое окно — болт летит ~900 px,
прогноз курса игрока неточен, особенно на дуге.

---

## 2. Целевые параметры

### 2.1. Cooldown между burst (CUT)

**Проблема:** в CUT режиме `tryFire()` открывает burst каждый кадр без
перезарядки.

**Решение:** добавить `FIGHTER_BURST_WINDOW` — минимальный интервал между
открытием fireGate в CUT режиме.

```
FIGHTER_BURST_WINDOW = 1.5  // секунды между burst в CUT
```

**Обоснование:** 1.5 с даёт игроку 0.6 с (40% окна) на то, чтобы понять
паттерн и начать манёвр. Это согласуется с планом дифференциации:
файтер — «дуэлянт», который наказает стояние, а не реакцию.

### 2.2. Commit range

**Проблема:** 620 px позволяет файтеру зайти с standoff дистанции и сразу
перейти в ATTACK.

**Решение:**

```
FIGHTER_COMMIT_RANGE = 400  // было 620
```

**Обоснование:** 400 px — это примерно 1.5 радиуса standoff (266 px).
Файтер должен подлететь ближе, прежде чем решиться на заход. Это даёт
игроку ~0.4 с на реакцию (при скорости сближения ~250 px/s).

### 2.3. Fire max time

**Проблема:** 1.25 с — болт летит 900 px, прогноз курса на дуге неточен.

**Решение:**

```
FIGHTER_FIRE_MIN_TIME = 0.2    // было 0.12
FIGHTER_FIRE_MAX_TIME = 0.9    // было 1.25
```

**Обоснование:**
- Минимум 0.2 с — убирает выстрелы «в упор» (менее 0.12 с болт пролетает
  всего 144 px, угловой размер цели слишком велик).
- Максимум 0.9 с — болт летит ~650 px, прогноз курса на дуге остаётся
  точным.

### 2.4. Burst interval

**Проблема:** 0.09 с — слишком короткий, создаёт ощущение «пулемёта».

**Решение:**

```
FIGHTER_BURST_INTERVAL = 0.12  // было 0.09
```

**Обоснование:** 0.12 с — всё ещё почти мгновенная очередь (ощутимо быстрее
человеческой реакции ~0.25 с), но заметно менее «пулемётная».

### 2.5. Burst count

**Проблема:** 2 болта в очереди — нормально, но в сочетании с непрерывной
стрельбой в CUT создаёт чрезмерный DPS.

**Решение:** оставить 2.

**Обоснование:** 2 болта — это «очередь», а не «пулемёт». С новым cooldown
между burst DPS будет в допустимых пределах.

## 4. Ожидаемый результат после ребаланса

### Новый DPS в CUT режиме

- Burst: 2 болта × 0.12 с = 0.24 с на очередь
- + 1.5 с (burst window) = 1.74 с на цикл burst
- Средний DPS: 2 / 1.74 × 30% × 4.55 = **~3.13 урона/с**

### Новый цикл боя

| Фаза | Длительность | Действие | Урон |
|---|---|---|---|
| PATROL → SEARCH | ~1.5 с | Сближение | 0 |
| SEARCH → CUT | ~0.5 с | Облет | 0 |
| **CUT** | **~4 с** | **~2 burst** | **~5.5** |
| EVADE | 0.65 с | Вираж | 0 |
| COOLDOWN | 1.2 с | Свободный полёт | 0 |
| **Всего за цикл** | **~7.9 с** | **2 burst** | **~5.5** |

**DPS за цикл:** 5.5 / 7.9 = **0.7 урона/с** (как было, но теперь это
реалистичный цикл, а не непрерывная стрельба).

**За 15 секунд CUT (максимальный бой):** ~2.7 burst × 2.73 = **~7.4 урона**
(вместо ~41). Игрок может уклониться, прервав CUT манёвром.

### Восприятие игроком

- Файтер стреляет **очередями по 2 болта** — заметно, но не «пулемёт».
- Между очередями — **1.5 с пауза** — игрок видит паттерн и может маневрировать.
- Файтер подходит **ближе перед заходом** (400 px) — игрок видит телеграф.
- Выстрелы **«в упор» и «наверняка»** убраны — каждое попадание ощущается
  как заслуженное.

## 6. Критерии приёмки

- [ ] Файтер не ваншотит игрока за 15 секунд CUT (максимум ~15 урона).
- [ ] Между burst в CUT — пауза ≥ 1 с (игрок видит паттерн).
- [ ] Файтер не стреляет «в упор» (дистанция ≥ 150 px).
- [ ] Файтер не подтверждает окно на дуге > 0.9 с (прогноз точен).
- [ ] Файтер не заходит ближе 400 px без видимой угрозы.
- [ ] Цикл PATROL → SEARCH → CUT → EVADE → COOLDOWN проходит за 7–10 с.

## 7. Альтернативы (если основной план не утверждён)

### A. Только cooldown между burst (минимальное изменение)

Добавить только `FIGHTER_BURST_WINDOW = 1.5`. Остальные параметры оставить.

**Плюсы:** минимальный риск регрессии.
**Минусы:** commit range 620 px всё ещё позволяет слишком ранний заход.

### B. Уменьшить burst count до 1

**Плюсы:** мгновенно снижает DPS.
**Минусы:** файтер теряет «очередь» как механику — становится скучным.

### C. Увеличить HP игрока

**Плюсы:** компенсирует высокий DPS.
**Минусы:** не решает проблему, а маскирует её. Игрок всё равно получает
непредсказуемый урон.

**Рекомендация:** план из раздела 2 — он решает проблему в корне, не ломая
архитектуру и сохраняя «дуэлянтский» характер файтера.
