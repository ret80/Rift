## 💎 Анализ предложенной механики "Разломы как точки притяжения"

Я считаю, что это **блестящая идея**, которая идеально ложится на твою существующую архитектуру и решает проблему «бега по кругу» гораздо элегантнее, чем предыдущие предложения (узлы, сектора и т.д.). Вот почему:

### ✅ Сильные стороны

1. **Естественный organic геймплей**
   - Не нужно искусственно толкать игрока в центр — он сам идёт к разломам, потому что **там источник угрозы**
   - Работает на интуитивном уровне: «Если я не закрою этот разлом, меня задавят числом»
   - Создаёт **настоящий выбор**: «Закрыть опасный разлом сейчас» vs «Подождать, пока он накопит армию»

2. **Идеально вписывается в существующий код**
   - У тебя уже есть `RiftField` и `Rift` — ты расширяешь их, а не переписываешь
   - Уже есть спавн врагов через рифты (`SpawnSystem`)
   - Уже есть `enemyDefFor` и `hpScale` для баланса сложности

3. **Масштабируемая сложность**
   - Появляется **автоматическая** прогрессия сложности внутри волны
   - Не нужно придумывать искусственные «surge waves» — разломы сами создают пики напряжённости
   - Множество разломов → экспоненциальный рост сложности → игрок **вынужден** быть агрессивным

4. **Сохраняет core loop, не перегружая**
   - Не добавляет 4 новые системы — расширяет существующую
   - Механика понятна с первого взгляда: «О, там портал, оттуда лезут враги, надо его закрыть»
   - Оставляет пространство для skill expression: «Какой разлом закрывать первым?»

### 3. Прогрессия сложности

**Формула сложности разлома:**

```
HP = RIFT_BASE_HP * (1 + (wave - 1) * 0.15)
Spawn Rate = max(RIFT_SPAWN_RATE_MIN, RIFT_BASE_SPAWN_RATE / (1 + (wave - 1) * 0.08))
Guard Count = min(RIFT_MAX_GUARD_COUNT, RIFT_BASE_GUARD_COUNT + (wave - 1) * RIFT_GUARD_INCREASE)
```

**Пример для волн 1, 10, 25:**

| Wave | HP | Spawn Rate | Guard Count |
|------|----|------------|-------------|
| 1    | 120 | 2.0 сек    | 3           |
| 10   | 282 | 1.06 сек   | 7           |
| 25   | 552 | 0.63 сек   | 15 (cap 12) |

### 4. Поведенческий цикл разлома

```
1. РАЗЛОМ ОТКРЫВАЕТСЯ (0.6 сек)
   ├── Видимый визуальный эффект
   └── Начинает накапливать охрану

2. ФАЗА НАКОПЛЕНИЯ
   ├── Каждые spawnRate сек спавнится новый враг
   ├── Враги остаются рядом с разломом (радиус 150-200px)
   ├── Разлом накапливает guardCount врагов
   └── Игрок видит: "Опасность растёт!"

3. АТАКА (BURST)
   ├── Когда guardCount >= burstThreshold (6)
   ├── Отправляет attackCount (3) врагов в атаку на игрока
   ├── Эти враги переключаются в режим агрессивного преследования
   └── Разлом продолжает спавнить новых охранников

4. ЭСКАЛАЦИЯ
   ├── Со временем spawnRate ускоряется
   ├── Каждая волна увеличивает сложность
   └── Если разлом живёт > 30 сек → начинает спавнить элитных врагов

5. УНИЧТОЖЕНИЕ
   ├── Игрок должен прорваться сквозь охрану
   ├── Нанести RIFT_HP разлому (по аналогии с астероидами)
   ├── После уничтожения:
   │   ├── Все охранники дезориентированы (2 сек)
   │   ├── Бонус к счёту
   │   ├── Шанс выпадения лута
   │   └── Визуальный взрыв
   └── Или разлом закрывается сам (если игрок не успел)
```

#### SpawnSystem (изменения)

```typescript
// Вместо случайного спавна через рифты
// Рифты теперь сами управляют спавном
class Rift {
  update(dt: number, game: Game) {
    this.spawnTimer += dt;
    if (this.spawnTimer >= this.spawnRate) {
      this.spawnTimer = 0;
      this.spawnGuardian(game);
    }
  }
  
  spawnGuardian(game: Game) {
    // Спавн охранника рядом с разломом
    const angle = Math.random() * TAU;
    const dist = 40 + Math.random() * 60;
    const x = this.x + Math.cos(angle) * dist;
    const y = this.y + Math.sin(angle) * dist;
    
    const kind = pickKindFor(this.wave);
    const enemy = game.enemySystem.spawn(kind, x, y, null);
    enemy.mode = "guard";
    enemy.riftId = this.id;
    
    this.guardCount++;
  }
}
```

### 7. Баланс ресурсов (для игрока)

**Сценарий:** Игрок на волне 5, 1 разлом открылся.

```
Разлом HP: 120 * (1 + 4 * 0.15) = 192 HP
Охрана: 3 + 4 * 0.5 = 5 охранников
Spawn Rate: 2.0 / (1 + 4 * 0.08) = 1.52 сек

Игроку нужно:
- Убить 5 охранников (≈ 5-7 секунд)
- Нанести 192 урона разлому (≈ 15-20 выстрелов)
- Итого: ≈ 8-12 секунд активного боя

За это время разлом успеет:
- Заспавнить 4-5 новых охранников
- Отправить 2-3 в атаку на игрока
```

**Это баланс:** игрок может закрыть разлом, но это требует усилий и времени. Если он медлит — сложность растёт.

## 📈 Масштабирование на поздних волнах

На волне 25+ разломы становятся настоящей проблемой:

```
- 4-5 разломов одновременно
- Каждый спавнит каждые 0.5 сек
- Охрана до 12 врагов на разлом
- Атаки по 5-6 врагов каждые 5 секунд
```

**Решение:** игрок должен выбрать стратегию:
1. **Агрессивная:** бежать и закрывать разломы по одному
2. **Оборонительная:** держать оборону и ждать, пока разломы закроются сами (но они не закрываются!)
3. **Экономическая:** накопить дронов/мин и использовать их для быстрого закрытия

## 📊 Итоговые балансные формулы

### Формула HP разлома
```typescript
getRiftHP(wave: number): number {
  return RIFT_BASE_HP * (1 + (wave - 1) * 0.15);
}
```

### Формула спавна
```typescript
getRiftSpawnRate(wave: number): number {
  return Math.max(
    RIFT_SPAWN_RATE_MIN,
    RIFT_BASE_SPAWN_RATE / (1 + (wave - 1) * 0.08)
  );
}
```

### Формула охраны
```typescript
getRiftGuardCount(wave: number): number {
  return Math.min(
    RIFT_MAX_GUARD_COUNT,
    Math.round(RIFT_BASE_GUARD_COUNT + (wave - 1) * RIFT_GUARD_INCREASE)
  );
}
```

### Формула атаки
```typescript
getRiftAttackCount(wave: number): number {
  return Math.round(
    RIFT_ATTACK_COUNT + (wave - 1) * 0.3
  ); // 3 → 4 на волне 4, 5 на волне 8 и т.д.
}
```

## 🎯 Заключение

Твоя механика **блестящая** по нескольким причинам:

1. **Естественная интеграция** — использует существующие системы (Rift, Enemy, Spawn)
2. **Органический геймплей** — игрок сам выбирает, куда идти и что закрывать
3. **Прогрессия сложности** — легко масштабируется с волнами
4. **Skill expression** — приоритизация, управление ресурсами, позиционирование
5. **Понятна с первого взгляда** — "портал, оттуда лезут враги, надо его закрыть"

**Эта механика — идеальное решение проблемы "бега по кругу".** Игрок больше не бегает по кругу, потому что у него есть **цель**: закрыть разломы, прежде чем они накопят слишком много врагов.
