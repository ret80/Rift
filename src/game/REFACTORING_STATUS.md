# Статус рефакторинга Game.ts

## Проблема

Несмотря на создание новых модульных систем (EventBus, Player, Enemy, EnemyAI, WaveManager, ZoneManager, ScoreManager, PhysicsSystem), **основной файл game.ts остался монолитом** (~2500 строк) и не использует новые системы.

## Решение: Поэтапная миграция

### Этап 1: ✅ Завершен - Интеграция систем в Game.ts

**Выполнено:**
- Добавлены импорты всех новых систем в game.ts
- Создан новый конструктор Game с инициализацией систем:
  - `EventBus` - шина событий
  - `GameState` - состояние игры
  - `PhysicsSystem` - физика на kinetics.ts
  - `Player` - сущность игрока
  - `EnemyAI` - система ИИ врагов
  - `GameContext` - контекст для ИИ
  - `WaveManager` - управление волнами
  - `ZoneManager` - управление зоной
  - `ScoreManager` - подсчет очков

- Добавлен метод `updateSystems(dt)` который вызывает update у всех новых систем
- Сохранен метод `updateLegacy(dt)` для постепенной миграции старого кода

**Статус:** Новые системы интегрированы но legacy код все еще работает параллельно.

### Этап 2: ⏳ В процессе - Миграция логики по частям

**План миграции:**

1. **Миграция игрока (Player.ts)**
   - Перенести updatePlayer из game.ts в Player.update()
   - Перенести fireAll, updateMines в Player
   - Удалить дублирующийся код из game.ts

2. **Миграция врагов (EnemyAI + стратегии)**
   - Полностью заменить updateEnemies на EnemyAI.update()
   - Использовать стратегии для каждого типа врага
   - Удалить старый AI код из game.ts

3. **Миграция волн (WaveManager)**
   - Перенести initWave, buildQueue, spawnRift в WaveManager
   - Делегировать спавн врагов через EventBus
   - Удалить wave-логику из game.ts

4. **Миграция зоны (ZoneManager)**
   - Перенести updateZone в ZoneManager.update()
   - Обрабатывать события выхода за зону через EventBus
   - Удалить zone-код из game.ts

5. **Миграция коллизий (PhysicsSystem)**
   - Заменить updateBullets на PhysicsSystem
   - Использовать события physics_collision
   - Удалить ручные проверки коллизий

6. **Миграция рендеринга**
   - Создать EntityRenderer, HUDRenderer
   - Вынести drawGame в отдельные рендереры
   - Каждая сущность рисует себя сама

### Этап 3: 🔜 Будущее - Финальная очистка

После полной миграции:
- Удалить updateLegacy() полностью
- Удалить все private поля дублирующие состояние систем
- Game.ts сократится до ~150 строк чистого оркестратора


## Как работать с кодом во время миграции

1. **Новый код** пишите сразу в соответствующие системы (Player, EnemyAI, и т.д.)
2. **Старый код** постепенно переносите и удаляйте из game.ts
3. **Тестируйте** что новая система работает корректно перед удалением старой
4. **Используйте EventBus** для связи между системами вместо прямых вызовов

## Преимущества новой архитектуры

✅ **SOLID**: Каждый класс отвечает за одну задачу  
✅ **Testable**: Системы можно тестировать изолированно  
✅ **Extensible**: Новый тип врага = новая стратегия без изменения ядра  
✅ **Maintainable**: Легко найти где какая логика находится  
✅ **Decoupled**: Системы общаются через EventBus, не зависят друг от друга напрямую
