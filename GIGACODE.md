# Правила разработки для проекта РАЗЛОМ

## 1. Удаление неиспользуемого кода
- При реализации нового кода немедленно удалять старый неиспользуемый код
- Не оставлять закомментированные блоки кода
- При рефакторинге удалять устаревшие функции, переменные, интерфейсы
- Не накапливать "мёртвый" код — если что-то не используется, удалять сразу

## 2. Анализ проблем
- Глубоко анализировать проблему перед внесением изменений
- Не предпологать — проверять код, логи, стек вызовов
- Если причина проблемы не найдена после анализа — спрашивать у пользователя
- Предлагать варианты решения и спрашивать какие проверить
- Не придумывать несуществующие проблемы

## 3. Принципы SOLID
- **S** — Single Responsibility: один класс/функция отвечает за одно дело
- **O** — Open/Closed: классы открыты для расширения, закрыты для модификации
- **L** — Liskov Substitution: подклассы должны заменять базовые без последствий
- **I** — Interface Segregation: много маленьких интерфейсов лучше одного большого
- **D** — Dependency Inversion: зависеть от абстракций, не от конкретики

## 4. Язык комментариев и документации
- Все комментарии в коде на русском языке
- Документация JSDoc на русском языке
- Описание предназначения функций, классов, модулей на русском
- Переменные и имена функций на английском (как стандарт индустрии)

## 5. Рефакторинг
 - Избегай адаптеров. Если делаешь рефакторинг то нужно переделывать все системы которые плохо спроектированны а не пытатся создать тысячу адаптеров. Адаптеры сильно усложняют понимание проекта, делают код трудночитаймым и плохо поддерживаемыми.
